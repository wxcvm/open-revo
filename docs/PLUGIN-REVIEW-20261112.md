# D:\QQ 插件审查与电源页滚动修复

## 范围与证据

检查六个压缩包（MRO HUD 包内实际包含两个插件）。原文件保持不变，仅将副本解压到验证目录。
未安装这些插件，未启动包内 EXE、BAT、代理、驱动、RTSS 或登录任务，也未请求代理的本地 HTTP 端点。
DeepSeek Harness 负责独立静态审查，主代理核对宿主分支、清单、关键源码，并使用 REA 对两份二进制做静态身份检查。

## 必须区分的证据

- 原始 Harness 审查把通用 EC 钥匙库误关联到 P916F，又把另一平台的门控值当作本机已知值；该推断不成立。本机已验证的是专用 PMC2 通道，不据此移植通用 EC 地址。
- HUD 包里确实有 RTCoreMini 驱动文件，但“包内存在”不证明启动 HUD 必定加载它们。可确认的源码行为是代理会尝试启动 RTSS；本轮未执行这些产物。
- SDT 的 DLL 内存在 StrixPoint/Zen5 名称，纠正“完全没有该代号线索”的过强结论；仍不能推导其方法在本机有效。
- 提供的 C# 源码没有做逐字节可重现构建验证，不能证明包内 EXE 与源码完全一致。PBO 原生侧车本轮只做身份/字符串检查，没有反编译完整控制流。
- MRO HUD 的风扇百分比以固定 5000 为分母；本机没有已校准的最高转速合同，若吸收 HUD，应改为仅显示有效转速或使用已验证上限，不能直接沿用这个百分比。

## 电源页滚动根因与修复

旧 `.power-view-container` 使用 `height:100%`、`max-height:658px`、`overflow:hidden`。
新增 CPU、原生限充和场景后内容超过此高度，但外层 `.shell-viewport` 看不到被隐藏的溢出，所以滚轮无法到达下半页。

改为自然高度、顶部排列、子区块不收缩；由已有 `.shell-viewport` 统一负责滚动，不再创建第二层滚动区域。
`tools/power-scroll-ui.test.cjs` 加载真实电源组件、真实样式及同一壳层布局，硬件 IPC 全部模拟且断言没有写入命令。

- 修复前：1280×800 下滚轮位置仍为 0，底部在视口之外，回归测试正确失败。
- 修复后：1280×800、960×640，CPU 收起/展开共四种组合，滚轮均可到底并回顶，最末电池区块可见、区块不重叠、导航位置不变。
- 已安装 WebView2 的实际滚轮验收另记于交付目录，不以模拟 IPC 浏览器测试替代。
